# 复刻 n8n 界面：评估与分期计划（只计划，不执行）

日期：2026-11-05
状态：已定档（B 档），待开工
范围：这是**评估文档**，不含任何代码改动。按下面的批次逐批实施。

---

## 1. 先说结论

| 档位 | 内容 | 工作量 | 建议 |
| --- | --- | --- | --- |
| A 皮相 | 只换视觉语言：配色/节点卡/画布 chrome/暗色 | 10–14 人日 | 便宜，但"像 n8n 的架构图工具"，交互还是我们自己的 |
| **B 皮相 + 交互骨架** | 外壳（左栏/顶栏/标签页）+ 节点卡 + 插入面板 + NDV 壳 + 运行态演示 | **33–44 人日（约 6.5–8.5 周）** | **已定档：做这个**，每 5–7 天一批可发布 |
| C 功能等价 | 加上执行引擎、节点参数 schema、凭证、数据流、表达式运行时 | 3–6 个月，等于另做一个产品 | 不建议 |

关键判断：n8n 的"界面"不是一层皮，而是**三件套**——画布上的节点卡、点 `+` 弹出的节点面板、双击节点打开的 NDV（Node Detail View）。其中 NDV 占整体工作量的一半左右，因为它要求"每个节点类型有自己的参数表单"。我们现在的属性面板是 1168 行的通用面板（所有节点共用），这是最大的结构性差距。

另外 n8n 的核心承诺是"**能跑**"：节点会亮绿灯、会出数据、会报错。我们是静态架构图工具，没有运行时。所以 B 档必须做一个明确的取舍：要么"演示模式"（前端假跑，按拓扑点亮 + 假日志，UI 上标注"演示"），要么干脆不做运行态。这个决定影响 3–5 人日和产品定位，见 §6。

## 2. 法务与品牌（先看清红线，再谈像素）

n8n 的代码是 **Sustainable Use License**（fair-code）：允许自用/内部业务/非商业使用与修改，**商用分发需另签协议**；商标使用受法律限制（[官方许可说明](https://docs.n8n.io/n8n-community-license/community-license.md)）。

所以"完全复刻"要拆成两件事：

- ✅ 可以：借鉴布局范式、信息层级、交互习惯（这是行业通用的 UI 模式），用自己的代码与设计语言实现。
- ❌ 不可以：直接拷 n8n 的前端代码（Vue，且许可证限制商用）；复制它的 Logo、品牌插画、文案；把 AWS/GCP/Slack 等第三方 logo 打包进我们的节点图标（那些是各自商标）。

结论：本次做的是 **"n8n 风格"的原创实现**，保留我们自己的名字、图标集（现在用 tabler）、中文文案。像素级 1:1 拷屏不做——既有法律风险，也没有意义（我们的用户是画架构图的，不是搭自动化的）。

## 3. 现状盘点（我们手上有什么）

```
apps/web/src  11,888 行，27 个测试文件，350 用例
组件：TopBar 373 / Canvas 897 / PropertyPanel 1168 / Gallery 428 / LayerPanel 212 …
画布：@xyflow/react 12，32 类节点 + 特殊节点（文本/元素/便利贴/线条/泳道/分组）
存储：Zustand + Supabase（arch_ 前缀）；游客模式 localStorage
```

对得上 n8n 的部分：画布引擎、框选/多选、右键菜单、快捷键、暗色变量（我们已有 CSS 变量但只做了浅色）、导出、版本历史、搜索对话框。

缺的部分：左栏图标导航、多标签页、节点卡（图标方块 + 副标题 + 状态点 + 端口加号）、插入面板（搜索 + 分类 + 键盘导航）、NDV、执行态、表达式编辑器、暗色主题。

## 4. 逐区域评估

| n8n 区域 | 我们的现状 | 差距 | 工作量 | 风险 |
| --- | --- | --- | --- | --- |
| 左栏图标导航（Workflows/Executions/…） | 无（只有组件库 240px） | 新建，且要把组件库改成"抽屉"（刚做完手柄那套正好复用） | 2–3d | 低 |
| 顶栏：面包屑 + 工作流名 + 保存状态 + Share + Active 开关 + Execute | TopBar 已有图名/保存/撤销/版本/导出 | 重排 + 新增 Active/Execute 位（未接引擎时是装饰） | 2–3d | 低 |
| 多标签页（同时开多个工作流） | 无（路由是单图） | 需要 store 支持多文档 + 标签栏 | 3–4d | **中**：撤销栈/保存队列要按标签隔离，容易出脏数据 |
| 节点卡（图标方块 + 标题 + 副标题 + 状态点 + 端口） | ArchNode：圆角卡片 + 图标 + 名称 + 副文本 | 重画组件 + 端口交互，需保住现有 32 类节点、分组/泳道/特殊节点 | 3–4d | 中：节点卡变复杂，200 节点图的性能与命中区域要复测 |
| 画布 chrome（点阵、悬浮加号、左下缩放、minimap、暗色） | 已有网格/缩放/minimap（部分开关） | 加"连线上悬浮 + 插入节点"，视觉对齐 | 3–4d | 中：插入加号的命中逻辑与框选/连线选取会打架（我们刚做完框选规则，必须回归） |
| 插入面板（搜索 + 分类 + 预览 + 键盘） | ComponentPanel：搜索 + 分类卡片（240px 常驻） | 改成弹出面板 + 右侧预览 + 键盘上下选择 | 4–5d | 低 |
| NDV（节点详情：左参数 + 右数据 + 执行/固定数据） | PropertyPanel 1168 行通用面板 | **推倒重建**为"每类节点一套参数 schema" | 8–12d | **高**：要引入 `nodeType → params` 的 Zod schema、旧图迁移、与现有多选批量编辑并存 |
| 数据预览（Table/JSON/Schema） | 无 | 只读渲染（假数据或节点自定义字段） | 3–4d | 中：表格虚拟滚动；我们其实没有"数据"，只能是节点属性预览 |
| 表达式编辑器 `{{ }}` | 无 | 只读高亮或轻量输入（不做补全/变量树） | 2–6d | 中：做全就是 6d+，做壳 2d |
| 执行态（节点绿灯/红错/耗时）+ 执行日志抽屉 | 无运行时 | 演示模式：按拓扑顺序点亮 + 假日志 | 3–5d | **中高**：容易被当成真执行，必须在 UI 明示"演示"；不做则这项归零 |
| 右键菜单 / 快捷键 | 已有 ContextMenu + 快捷键 | 补 n8n 习惯（如 Ctrl+Enter、双击进 NDV） | 1–2d | 低 |
| 暗色主题 | CSS 变量已有，浅色 | 变量全量映射 + 组件自查 | 3–4d | 中：Canvas 里还有硬编码色值，要逐个换 |
| 回归与文档 | 350 用例 / 验收记录 | UI 大改需补截图回归（Playwright） | 4–5d | 中：新增依赖要决策 |

合计（B 档，含"演示模式"与"只读表达式"）：**33–44 人日**，按我们近几批的节奏约 **6.5–8.5 周**；不含 C 档执行引擎。

关键路径：P4 最长且不可压缩（schema 设计 + 迁移）。建议 P1/P2 先行，因为它们是"看起来像"的主要来源；P4 单独一批做，期间保持功能开关（旧属性面板可回退）。

## 6. 已拍板（2026-11-05）

| 决策 | 结果 | 影响 |

开工顺序：P0（只写规格文档，不动代码）→ P1 → P2 → P3 → P4 → P5 → P6 → P7。每批独立 commit + push + Pages 部署 + 线上实测。

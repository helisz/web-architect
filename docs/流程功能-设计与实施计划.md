# 流程（Flow）功能 · 设计与实施计划

> 状态：**已确认，开工中**（2026-11-08）
>
> 已定：① 跨域走「目标系统开 CORS」；② 新建一套 flow 专用表；
> ③ 登录后进产品选择页；④ 管理员用 Supabase `app_metadata.role = 'admin'` 判定；
> ⑤ 普通用户可建私有模板；⑥ 节点存模板快照 + 「同步到最新」；⑦ 首版不做轮询。

## 3. 模板节点配置（`flow_template.config`）

```jsonc
{
  "version": 1,

  // —— ① 数据源 ——
  "data": {
    "method": "GET",                  // GET | POST
    "url": "https://api.example.com/status/{{env}}",
    "headers": [{ "key": "Authorization", "value": "Bearer {{token}}", "secret": true }],
    "query":   [{ "key": "app",  "value": "{{app}}" }],
    "body":    "[{ \"key\": \"ids\", \"value\": \"{{id}}\" }]",   // 仅 POST
    "timeoutMs": 10000
  },

  // —— ② 节点参数（用户建节点时填，URL/headers/body 里用 {{name}} 引用）——
  "params": [
    { "name": "app",   "label": "应用名", "required": true,  "default": "" },
    { "name": "token", "label": "令牌",   "required": false, "default": "", "secret": true }
  ],

  // —— ③ 字段展示 ——
  "display": {
    // 展示哪些 key（可改名、可设高亮）
    "fields": [
      { "path": "data.status",    "label": "状态",   "highlight": true  },
      { "path": "data.version",   "label": "版本",   "highlight": false },
      { "path": "data.owner.name","label": "负责人", "highlight": true  }
    ]
  },

  // —— ④ 状态判定 ——
  "status": {
    "path": "data.health",            // 取哪个 key 判状态
    "success": ["ok", "healthy", "UP"],   // 命中即成功
    "failure": ["down", "error"],          // 命中即失败
    // 都不命中 = 未知（灰色）
  },

  // —— ⑤ 跳转 ——
  "system": {
    "label": "跳转到运维平台",
    "url": "https://ops.example.com/app/{{app}}"
  }
}
```

**key 路径语法**：点号路径 + 数组下标，如 `data.items[0].name`；也接受 `data.items.0.name`。

## 4. 显示模式（流程详情页）

打开流程 → 每个节点自动请求一次（§6 的时机规则），节点卡片显示：

```
┌──────────────────────────────┐
│ ● PostgreSQL 主库      [刷新] │  ← 状态点：绿/红/灰
│ ──────────────────────────── │
│ 状态        healthy  ← 高亮   │  ← 只有 highlight 的 key 常显
│ 负责人      张三     ← 高亮   │
│ 版本        12（折叠）        │
│ … 还有 8 个字段  [展开]       │  ← 其余默认折叠
│ ──────────────────────────── │
│        [ 跳转到运维平台 ]     │
└──────────────────────────────┘
```

- **默认折叠**：只显示 `highlight: true` 的字段，其余收在「展开」里；
- **状态点**：按 `status` 配置判定，失败时卡片描边转红；
- **请求失败**：节点显示错误摘要（HTTP 状态 / 超时 / CORS），状态点变红，可重试；
- **跳转按钮**：有 `system.url` 才出现，`target="_blank" rel="noopener"`。

## 5. 模板与节点的关系（重要）

节点引用模板时**存一份模板配置的快照**（`flow_node.template_snapshot jsonb`），而不是只存 `template_id`：

- 模板被管理员改动，**不会**让已有流程里的节点突然换行为（避免"昨天的图今天全红了"）；
- 节点上提供「同步到最新模板」按钮，用户主动更新。

> 如果你更想要"改模板即全局生效"，这条可以换成纯引用。**待你确认**（见 §9 Q3）。

## 6. 请求执行

- **时机**：进入流程详情 / 手动点刷新 / 节点参数改完后回车。
- **不做自动轮询**（首版）。需要的话后续加"每 N 秒刷新"开关。
- **并发**：一次流程刷新时，节点请求并发（上限 6），单个超时 10s。
- **CORS**：按你选定的方案 A —— **目标系统需放行 `Access-Control-Allow-Origin`**；请求失败时界面直接显示"跨域被拦"，并给出排查提示，不静默。
- **密钥**：`secret: true` 的参数（token 等）存 `flow_node.params` 里，跟着流程一起落库；RLS 已保证只有创建者能读。**不做额外加密**（除非你要求）。

---

## 7. 权限

- 现有模型是"每人只看自己的"（`creator_id = auth.uid()`）。
- 模板额外放开：`visibility = 'public'` 的模板所有人可读。
- **管理员**：现在系统里没有角色概念，需要一个判定依据 —— **待你确认**（见 §9 Q1）。

## 8. 分阶段实施

| 阶段 | 内容 | 产出 | 估时 |
| --- | --- | --- | --- |
| **P0** | 数据库：4 张新表 + RLS + 幂等 patch SQL | `supabase/patch-flow.sql`，跑完 `check:db` 能验证 | 0.5d |
| **P1** | 路由 + 产品选择页 + 流程列表（空壳） | 能进 `#/home` 选两个入口、看到流程列表 | 0.5d |

| **P3** | 单节点调试：填参数 → 发请求 → 原样显示返回 JSON → 试映射 | 模板编辑页右侧"调试"面板 | 1d |
| **P4** | 流程画布：复用现有画布组件 + 标准节点渲染（显示模式） | 能建流程、拖节点、连线、自动请求、显示字段、跳转 | 2d |
| **P5** | 收口：错误态、空态、加载态、导出、文档 | — | 0.5d |

合计约 **6 天**（按"可用增量"计）。P0–P2 可以先行，P4 是最大块。

## 9. 待你确认

### Q1. 管理员怎么判定？
现在没有角色系统。可选：
- **a)** 环境变量/常量里写死几个管理员邮箱（最简单，改代码才生效）
- **b)** Supabase 里加一张 `arch_admin`（或 `flow_admin`）表，手动加人
- **c)** 用 Supabase Auth 的 `app_metadata.role`（在 Dashboard 里给用户打标记）
- **d)** 先不做管理员：所有登录用户都能建模板，`visibility` 自己选（最快落地）

### Q2. 普通用户能不能建自己的私有模板？
- **a)** 能：可以建私有模板 + 用公共模板（推荐，灵活）
- **b)** 不能：只能用管理员建的公共模板（更可控）

### Q3. 模板改动对已有节点的影响？
- **a)** 快照：已建的节点不受影响，提供「同步到最新」（推荐）
- **b)** 实时引用：改模板立即对所有流程生效

### Q4. 首版要不要自动轮询？
- **a)** 不要，只手动刷新（推荐，先跑通）
- **b)** 要，节点上可设"每 30s / 60s / 5min 刷新"

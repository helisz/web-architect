# 运行手册

面向"把项目跑起来 / 长期维护"的人。使用操作看 [使用说明](使用说明.md)，逐条验收证据看 [验收记录](验收记录.md)。

## 1. 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| Node.js | ≥ 20（实测 v25.2.1） | `npm` 走 workspaces，`apps/web` 与 `packages/schema` 两个包 |
| 浏览器 | Chrome / Edge / Firefox 近两年版本 | 依赖 `foreignObject`、`html-to-image`、`ResizeObserver` |
| Supabase | 任意项目（可与其它项目共用实例） | 所有对象带 `arch_` 前缀，见 [ADR-0003](adr/0003-table-prefix.md) |

## 2. 首次部署（三步）

1. **建表 + 保存函数**：Supabase Dashboard → SQL Editor → 粘贴 [`supabase/schema.sql`](../supabase/schema.sql) **全文** → Run。
2. **增量保存函数（阶段 3 起需要）**：同样在 SQL Editor 里跑 [`supabase/patch-diagram.sql`](../supabase/patch-diagram.sql)。
   不跑也能用，前端检测到 404 会自动回退整图保存；跑完文件末尾有 `notify pgrst, 'reload schema'`，等几秒再刷新页面。
   这个文件同时负责**结构升级**：顶部有 `alter table arch_group add column if not exists sub_label ...`，
   老库升级到 v1.24（分组副文本）就是重跑它；可重复执行，不会动数据。
2b. **分组连线（2026-11-04 起需要）**：跑一次 [`supabase/patch-edge-group-endpoints.sql`](../supabase/patch-edge-group-endpoints.sql)，
   把 `arch_edge.source_node_id` / `target_node_id` 上指向 `arch_node` 的两个外键去掉 —— 分组（`arch_group`）
   也要能当连线端点，而一个 uuid 列没法同时外键到两张表，所以改由应用层保一致性（删组/解组时同时删线）。
   不跑的表现：节点之间的连线照常保存，**从/到分组的连线保存会报外键错误**，已有数据不受影响。
3. **环境变量**：`copy .env.example .env.local`，填 `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`。

自检：

```bash
npm run check:db      # 5 张表 + RPC 连通性，最后两项是 arch_save_diagram / arch_patch_diagram
```

## 3. 常用命令

```bash
npm install                     # 只在依赖变化时跑
npm run dev                     # 开发服务器，固定 http://127.0.0.1:5273
npm test                        # Vitest 全量（147 通过 / 1 跳过：RPC 契约用例需真实库）
npm run typecheck               # 两个包一起 tsc --noEmit
npm run build                   # 产物在 apps/web/dist
npm run check:db                # 数据库自检
npm run smoke                   # 冒烟：CDP 打开页面，校验能启动、能载图、无报错
```

> 端口固定 5273：本机 5173 被别的项目占用。要改端口用 `npm run dev -- --port 5280`。
> 构建后把 `apps/web/dist` 丢到任意静态服务器即可；路由用 **hash**（`#/` 图库、`#/d/<id>` 某张图），服务端不需要配 rewrite —— 任何路径都只回 `index.html`。

## 4. 性能开关与两档压测

| 位置 | 机制 | 阈值 / 效果 |
|---|---|---|
| `apps/web/src/canvas/Canvas.tsx` | `onlyRenderVisibleElements` | **≥ 300 节点**才打开：只渲染视口内的节点，平移到别处不再渲染全图 |
| `apps/web/src/canvas/Canvas.tsx` | 拖动期间冻结 `edges` / 障碍数组 | 拖动开始冻结，松手解冻；被拖节点的相邻边靠 `useInternalNode` 自动重画 |
| `apps/web/src/canvas/flowMapping.ts` | 节点/分组 flow 对象的 `WeakMap` 缓存 | 数据对象没变就复用同一个 ReactFlow 节点对象，`memo` 生效 |
| `apps/web/src/canvas/OrthoEdge.tsx` | 路径 `useMemo`（端点矩形 + 锚点 + 障碍数组） | 只有端点变了的边重算 `buildOrthoPath` |
| `packages/schema/src/ortho.ts` | `RectIndex` 240px 空间网格 | 障碍矩形 > 48 个才启用；2000 矩形查询在毫秒级 |

实测（300 节点 / 300 连线，开发服务器 + 真实浏览器，CDP 采集帧间隔）：

| 场景 | 优化前 | 优化后 |
|---|---|---|
| 连续移动节点（store 逐帧派发） | p50 160ms / p95 169.5ms | p50 16.5ms / p95 22.3ms |
| 真实指针拖动 | — | p50 16.6ms / p95 18.2ms / max 19ms |
| 首次挂载 300 节点 | — | 211ms |
| 9 节点小图拖动 | — | p50 16.5ms / max 18ms |

压测脚本按需重跑（脚本不进库，在 `.cache/` 下，已被 git 忽略）：`.cache/acc-perf300.mjs`、`.cache/acc-perf-drag.mjs`。

**1000 节点档位（生产包）**：先 `cd apps/web && node ../../node_modules/vite/bin/vite.js build`，再 `vite preview --port 5274`，然后 `node .cache/acc-perf1k-prod.mjs`。实测：挂载 262–385ms、指针拖动 p50 16.6ms、边标签在缩放 < 0.5 时自动跳过；非拖拽式坐标变更约 116ms/帧（DOM 重绘上限，见[验收记录](验收记录.md)「已知限制」）。

**冒烟脚本**：`npm run smoke`（= `node scripts/smoke.mjs`）用 CDP 打开页面，校验画布渲染、store 里有节点、控制台无 exception；失败退出码 1，可直接挂到 CI / pre-push。生产包要加 `?testhook` 才会挂 `__archStore`，否则只校验画布。

> 根路径现在是图库（没有画布），所以脚本会先用 `.env.local` 里的 anon key 问 REST「哪张图有节点」，再打开 `#/d/<id>`；也可以 `--diagram <id>` 指定，或 `--base http://127.0.0.1:5274` 换端口。

> 冒烟**只读**：脚本在页面加载前就拦掉 `arch_save_diagram` / `arch_patch_diagram`，并屏蔽 `arch:draft:` / `arch:viewport:` 的本地写入。不这么做的话，浏览器里残留的草稿会让页面变「脏」→ 自动保存 → 把用户的图白白 +1 个版本（这次真的踩到了：v323 → v324）。跑完请对比一下 `updated_at` 确认没被写。

> 冒烟**自己开一个标签页，跑完自己关掉**（`PUT /json/new` → `/json/close/<id>`），不再复用"第一个 page target"。2026-11-04 就是因为复用，把用户正在编辑的那个标签页当冒烟页导航走了、跑完又一起关掉——没保存的编辑会直接丢。现在浏览器里可以一直开着你的图。

> ⚠️ 做压测**不要**拿正在用的图跑：脚本会临时换成 300 节点的临时图，结束要恢复原图并软删临时图。撤销/重做压力测试同理 —— 历史栈里可能留着更早的测试态，回放会把节点带回或带走。

## 5. 数据与恢复

| 场景 | 做法 |
|---|---|
| 误删节点 | 撤销，或 `版本` 抽屉回滚到前一个快照 |
| 误删整张图 | 图库是**软删**（`arch_diagram.is_deleted = true`）；把该行改回 `false` 即恢复，或用快照回滚 |
| 多标签页"版本冲突" | 正常情况下第二个标签页会自动退为跟随者（不再写库）；真冲突时黄条给两个选择：放弃本地 → 重新载入；或用本地覆盖 |
| 页面崩了 / 误关，改动没存上 | 重开同一张图会自动比对本地草稿并恢复，顶部提示"已恢复上次未保存的改动" |
| 数据库里内容比页面新 | 刷新页面即可（bootstrap 载入最近更新的那张图） |
| 想彻底清空测试产物 | `arch_*` 五张表；节点/连线/分组是软删，主表 `arch_diagram` 软删后图库不再显示 |

快照策略：**首次必存** + **每 50 个版本** 或 **距上次 ≥ 30 分钟**（先到），由 `arch_save_diagram` / `arch_patch_diagram` 在服务端判断。回滚 = 以快照内容发起一次新保存，版本号 `max + 1`，历史不丢（D7）。

> 这里从"每 5 版"放宽到"每 50 版"是 2026-11-04 的改动（ADR-0008），目的是把写库次数压下来。手工快照（版本抽屉里的"存为快照"）不受影响，重要节点建议手动打一版。

### 5.1 保存策略（ADR-0008）

| 改动 | 什么时候写库 |
|---|---|
| 增删节点 / 连线 / 分组 | 空闲 **1 秒** |
| 改颜色 / 文字 / 位置 | 空闲 **3 秒** |
| 连续编辑不停手 | 满 **30 秒** 强制写一次 |
| 两次写库之间 | 至少隔 **10 秒** |
| 平移 / 缩放 | **不写库**（只存浏览器本地） |
| Ctrl/Cmd+S、回滚、导入 | 立刻写 |

想看效果：`select version, created_at from arch_snapshot order by version desc limit 20;` —— 最多的也就 2 小时 4、5 条（以前是几十条）。崩溃兜底靠 `localStorage` 里每 1.5 秒覆盖一次的 `arch:draft:<diagramId>`。

## 6. 排障

| 现象 | 原因 / 处理 |
|---|---|
| 首屏红屏「打开架构图失败」 | Supabase 不可达，或 `arch_save_diagram` 没建；跑 `schema.sql` 后 `npm run check:db` |
| 保存徽标一直红 | 看红条文字；`VERSION_CONFLICT` = 别处改过，选覆盖或重载 |
| 增量保存没生效 | 没跑 `patch-diagram.sql`，或者 PostgREST 还没 reload schema；刷新页面会重试 |
| 导出 PNG/SVG 报「找不到画布」 | 导出前清选中态失败，通常发生在刚切换视图；重新点一次即可 |
| PDF 里图很糊 | PDF 是 2× 位图嵌入（不是矢量），A3 横向更清晰；要矢量请用 SVG |
| 组内节点拖不出来 | 松手时按节点**中心**判定，中心还在组内就留在组里（C10） |
| 折叠组里的节点不显示 | 预期行为：数据还在，展开即回来（C9） |

## 7. 代码地图

```
apps/web/src
├─ canvas/        Canvas（ReactFlow 容器 / 事件）、flowMapping（数据 ↔ ReactFlow）、ArchNode、SwimlaneNode、OrthoEdge
├─ components/    TopBar、ComponentPanel、PropertyPanel、StatusBar、ContextMenu、SearchDialog、LayerPanel、Gallery、VersionDialog…
├─ data/          diagramRepo（REST/RPC）、usePersistence（防抖 + 串行保存 + 冲突）、payloadDiff（PATCH 差异）、transfer（导入导出）、snapshotRepo
├─ export/        exportPng（PNG/SVG 序列化）、exportPdf（位图 → PDF）、exportCsv
└─ store/         useDiagramStore（单 store：图数据 + 选中 + 历史 + UI 开关）

packages/schema/src
├─ types.ts / constants.ts / factory.ts     数据契约与默认值
├─ zod.ts / validate.ts                     单一校验源（V1–V10）
├─ ortho.ts                                 正交路由（含 RectIndex 空间索引与冲突绕行）
└─ convert.ts                               DB 行 ↔ Diagram 组装
```

## 行为约定

1. **创建即写入**：`createNode(nodeType, …)` 自动带 `extJson.iconKey`，调用方无需关心；
2. **手工覆盖保留**：`extJson.iconKey` 只要是允许集合内的合法值就**原样保留**（M2 属性面板的图标选择器可以直接改），只有缺失 / 非法 / `data:` / url 才被 V11 改写；
3. **未知类型兜底**：`iconKeyFor()` 对不在 32 类型表里的输入返回 `tabler:cube`；
4. **改表的代价**：以后调整图标只改 `ICON_KEY_BY_NODE_TYPE` 一处，历史数据下次保存自动跟随（除非被手工覆盖）。

## 剩下仍会重复的图标（有意为之）

| iconKey | 类型 | 说明 |
|---|---|---|
| `tabler:arrow-right-square` | `lb`、`proxy`、`ingress`、`gateway`、`link` | 都属于"流量入口/转发"语义，重复是刻意的 |
| `tabler:database` | `db`、`cache`、`mq`、`oss` | 都是存储型，同上 |
| `tabler:kubernetes` | `k8s-cluster`、`namespace`、`deployment`、`service` | 都是 K8s 对象 |
| `tabler:shield-lock` | `firewall`、`waf`、`vpn`、`ids` | 都是安全设施 |
| `tabler:typography` | `text`、`legend` | 都是文字块 |
| `tabler:cube` | `group`、`zone`、`custom` | 容器/占位，靠边框和标题区分，不靠图标 |

如果某一组在真实图纸里经常同框、需要进一步区分，随时说，我再补 key —— 改动仍然只有一处。

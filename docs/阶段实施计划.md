## 0. 结论先行

1. **规格质量高**：Schema、DDL、API、验收清单齐全，可直接进入开发，不需要再补需求文档。
2. **真正的成本在画布交互**。规格约 60% 的描述量落在 §4（拖拽/连线/分组/撤销/对齐），这也是 bug 密度最高的地方。裁掉 AI 后，画布占比进一步升到约一半工作量。
3. **MVP 锁在"画布 + 统一 Schema + 持久化闭环"**：验证规格 §0.1 的红线——同一份 Schema 贯穿渲染、传输、入库。这条链路跑通后，后面都是加法。
4. **规格里有 14 处需先修正或澄清的点**（§1.3），其中 3 处会导致"拖动一次就整体漂移""节点渲染成内置 group"级别的返工，必须在写代码前定案。
5. **MVP 约 6 个工作日，全量约 15.5 个工作日**。若只要"能用"，砍掉 PDF/CSV 与右键菜单全集，可压到约 10 天。

## 1. 对规格的评估

### 1.1 完成度体检

| 维度 | 评分 | 说明 |
|---|---|---|
| 数据模型（§6） | 完善 | TS 接口 + 字段字典 + 校验规则 V1–V10 三者互相对齐，可直接落成代码 |
| 数据库（§7） | 完善 | PG DDL 可直接在 Supabase 执行（`gen_random_uuid()` 为 PG13+ 内置，无需扩展） |
| API（§8/§9） | 基本完善 | 13 个接口 + 统一响应包 + full/patch 两种写模式；缺鉴权与错误码表 |
| 画布交互（§4） | 详尽但最重 | 20+ 交互动作、状态机、路由算法给到伪代码级；占 MVP 工作量一半 |
| 导出（§12） | 偏薄 | 只给格式与实现建议，PDF 中文字体、html-to-image 与 viewport 的交互都没展开 |
| 验收（§14） | 好用 | 交互/数据/视觉三组 16 条可逐条自测，可直接转测试用例 |
| ~~AI（§10）~~ | 已裁除 | 整章不实现；其中"非法色回填""绝对/局部坐标换算"两条其实属于常规校验，保留在 `validate.ts` |

**缺口（规格没写、必须我补）**：登录/鉴权、错误码表、UI 文案语言、Supabase 连接与建库策略、`.env` 管理、图标资源来源、示例图 fixture。

> **v1.2 架构调整**：按你的决定改用 **toolbox 同构方案 —— 无自建后端**，浏览器用 anon key 经 PostgREST 直连 Supabase，写库走 Postgres 函数保证事务，权限边界交给 RLS。规格 §7 的 HTTP API 与 §9 的接口清单**不再实现**；`/api/health` 由前端探针 + `npm run check:db` 取代。理由与代价见 [ADR-0004](./adr/0004-no-backend.md)。

### 1.3 规格中需先定案的 14 个点

> 编号用于后续 commit / ADR 引用。前 3 条是**返工级**问题，必须在阶段 0 定案。

| # | 位置 | 问题 | 建议 |
|---|---|---|---|
| **C1** | §11.1 `toSchema` 的 `abs()` | 注释要求"必须是相对父组的局部坐标"，但 `abs()` 返回**绝对坐标**，与 §6.2、§10.2 规则 9 矛盾 | 分组/节点一律直接取 `n.position`，**删掉 `abs()`**；绝对坐标只用于导出包围盒 |
| **C2** | §11.1 `type: n.nodeType` | 32 种 `nodeType` 直接当 ReactFlow 节点类型名，其中 `group`、`default` 与 **ReactFlow 内置类型同名**，会互相覆盖；且要注册 32 个组件 | 统一用单一 `archNode` 组件 + `data.nodeType` 分派图标/默认尺寸；`swimlane` 单独一个类型；禁止用 nodeType 原名做类型名 |
| **C3** | §11.1 `zIndex: n.sort` 与 `Number(n.style?.width)` | resize 后 `style.width` 可能是 `"160px"` 字符串 → `Number()` 得 `NaN`，直接污染 Schema 并被 V6 拒绝 | 用 `parseFloat`，优先 `node.measured?.width`；`sort` 与 `zIndex` 解耦（sort 只做层级排序） |
| C4 | §6.4 V4 | 后端无法真正判断"坐标是相对还是绝对"（没有渲染信息） | 降级为启发式：节点矩形完全落在组外 → 报 warning 并自动换算；严格保证由前端负责 |
| C5 | §10.3 vs §7.3 | edge `label` 上限：JSON Schema 40 字符，DDL 255 | AI 裁除后 JSON Schema 不再需要，直接以 255 为唯一约束（前端 UI 提示 40）。**已消解** |
| C6 | §9.1 vs §9.3 | PUT 示例带尾斜杠 `/api/diagrams/6f2a.../`，清单无 | 统一无尾斜杠，路由 `strict` 关闭 |
| C7 | §9.2 | 失败包只有业务 `code`，未定义 HTTP 状态映射 | 补表：400 校验 / 404 不存在 / 409 版本冲突 / 500；业务 `code` 与 HTTP 同时返回 |
| C8 | §7.5 | "每 5 次保存存 1 次密档"粒度太粗，回滚点不可控 | 改为：首次必存 + 每 5 次 或 每 30 分钟（先到）+ 手动命名快照 |
| C9 | §4.3 + §11.2 | 折叠时组高度压缩为 40px，但没说 Schema 里 `height` 是否跟着改 | Schema 永远存**展开态** height；40px 只在渲染层生效。否则展开后尺寸丢失 |
| C10 | §11.2 `extent: 'parent'` | 设了 `extent` 后节点**拖不出父组**，而规格要求"拖出即移出分组" | 拖拽期间不设 extent，拖拽结束按命中判定重设 `parentId`；或 `extent: undefined` + 手动 clamp |
| C11 | §11.3 冲突绕行 | 每帧扫全部节点矩形，300+ 节点时 O(n²) | 段-矩形相交用 20px 空间网格加速；只对可视区节点计算 |
| C12 | §12 PDF | 中文字体嵌入未提；`svg-to-pdfkit` 默认字体不含中文，会出方块 | 改用无头 Chromium 打印，或显式嵌入思源黑体子集；MVP 不做 PDF |
| C13 | §6.2 vs §7.3 | `tags` 在 TS 里可选、DDL 里 `NOT NULL DEFAULT '{}'`；MySQL 版 `tags JSON` 与 PG `TEXT[]` 不等价 | 统一 `string[]`；PG 用 `TEXT[]`；缺失即空数组 |
| C14 | §2.3 / §8.5 | 800ms 防抖 + `baseVersion` → 单用户连续编辑也会自冲突（两个请求在途） | 保存走**串行队列**：同一 diagramId 同时只允许 1 个在途请求，后续合并；`requestId` 幂等兜底 |
| C15 | 用户补充规则（2026-11-04） | 节点图标若存 base64/URL，体积大、外链会失效、无法换肤 | 只存 `extJson.iconKey`，取值限定 10 个预定义 key；创建时自动匹配、校验器 V11 兜底；详见 ADR-0005 |

## 3. 阶段 0 · 工程地基（0.5 天）

**目标**：一次拉通"类型 → 校验 → 建表 → 读写"，避免后面边写边改 Schema。

1. **monorepo 骨架**
   - 根 `package.json`（npm workspaces：`apps/*`、`packages/*`）：`dev`、`build`、`test`、`typecheck`、`check:db`
   - `tsconfig.base.json`（strict）、`.gitignore`、`.env.example`（`VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`）
2. **`packages/schema`（单一事实来源，全仓库唯一允许定义结构的地方）**
   - `types.ts`：照抄规格 §6.2
   - `constants.ts`：`NODE_TYPES`、§3.3 九大分类树、§3.5 语义色、附录 B 默认尺寸与默认副文本、`TABLES`（物理表名）
   - `zod.ts`：与 types 一一对应的 Zod schema（**唯一校验源**）
   - `validate.ts`：V1–V10（V4 按 C4 降级，V9/V10 仅在持久化前调用）
   - `factory.ts`：`createDiagram/createNode/createGroup/createEdge`（默认值 + UUID v4）
   - `fixtures/sample-saas.json`：按规格 §10.5 复刻的标准样图，作为**全阶段回归基线**
   - 单测：V1–V10 每条一正一反；`toFlow↔toSchema` 往返无损（D2）
3. **建库（Supabase 直连，无需本地数据库）**
   - `supabase/schema.sql`：§7.3 DDL 的**列名/类型零改动**，所有表/索引/约束/函数/触发器统一 `arch_` 前缀（与 toolbox 共用同一实例，见 ADR-0003）；**可重复执行**（`if not exists` + `add column if not exists`），末尾有撞名自检与 RLS 段
   - 执行方式：Supabase Dashboard → SQL Editor → 粘贴全文 → Run（toolbox 同款）
   - `.env.local`：`VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY`（与 toolbox 同项目可直接复用）
   - `scripts/check-db.mjs`：`npm run check:db` 验证「可达 / 5 张表可读 / RLS 放行 anon 写 / CHECK 约束生效」
4. **`apps/web` 骨架**：Vite + React 18 + Tailwind，CSS 变量按 §3.4/§3.5；静态三栏 + 顶部栏 + 状态栏；`lib/supabase.ts` 客户端与缺变量自检

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 分组坐标换算写错（C1/C10） | 拖动一次全图漂移，最难查 | 阶段 0 定案 + M2 专项往返测试（A3 即回归点） |
| ReactFlow 内置类型名冲突（C2） | 节点渲染成内置 group，样式全乱 | 类型名加前缀，禁止裸用 nodeType |
| 正交路由复杂度失控 | 阶段 2 拖期 | MVP 只用 2 拐点简化版；完整绕行独立成纯函数，可单独迭代 |
| PDF 中文乱码（C12） | 交付物不可用 | 直接上无头 Chromium 打印，不做 svg-to-pdfkit |
| Supabase 免费项目闲置暂停 | 联调中途连不上 | 前端探针每 30s 探一次并在顶部栏显示；`npm run check:db` 一键定位是「没建表」还是「RLS 拦了」 |
| 与 toolbox 共用同一个库（额度不够） | 表名冲突、误改对方数据 | 所有对象加 `arch_` 前缀；`schema.sql` 可重复执行且带撞名自检（列不符即报错）；授权只针对本项目 5 张表 |
| anon key 随前端包公开（无后端方案的固有代价） | 拿到地址的人可读写 `arch_*` | 接受（仅内网使用）；`service_role` 绝不进前端；后续若需收紧，加 Supabase Auth + 按 `creator_id` 的 RLS 策略即可，无需改架构（ADR-0004） |
| 多表写入非事务导致数据半截 | 保存中断后图残缺 | 写入一律走 `arch_save_diagram` RPC（单事务），禁止前端逐表写 |
| 32 类图标工作量被低估 | 视觉不达标 | MVP 用统一几何占位 + 语义色；图标集作为独立任务放阶段 2 |
| 与另一项目共用同一个库（额度不够） | 表名冲突、误改对方数据 | 已定：本项目所有对象加 `arch_` 前缀（表/索引/约束/函数/触发器）；`schema.sql` 末尾有撞名自检，结构不符直接报错；授权语句只覆盖 `arch_*` 五张表 |

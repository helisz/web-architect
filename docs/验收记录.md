## 已知取舍

1. **`requestId` 幂等**：规格 §5.5 建议 5 分钟幂等键。实际用**版本号 + 行锁**做并发闸（重复提交同一基线会被 `VERSION_CONFLICT` 拦住），因此没有加 requestId 表。代价是"网络超时后自动重试"会表现为一次冲突提示；本项目前端不自动重试，故未触发。
2. **层级操作会导致一次全量补丁**：`sort` 归一化为 0..N-1 会改动所有行的 `sort` 字段，因此置顶/置底后第一次保存的补丁包含全部行。后续若要压这部分开销，可改为"只在层级冲突时局部调号"。
3. **绕行是候选枚举而非最优搜索**：每方向最多 12 条候选通道，按"压住节点数 → 折线长度"打分取最优。极端布局（多节点围成口袋）仍可能出现一条较绕的线，但不会压节点。
4. **搜索范围**：`label / subLabel / extJson.ip`（规格 §11.3 要求），不支持正则与按类型筛选。

## 已知取舍

1. **PDF 不是矢量**：节点是 HTML，SVG→PDF 转换器都不渲染 `foreignObject`（实测 `svg-to-pdfkit` 出空白页），因此 PDF = 2× 位图嵌入。要矢量用 SVG，要设计工具兼容用 PNG。
2. **SVG 的 `foreignObject` 限制**：浏览器能开，Figma/Visio 不能。见 ADR-0006。
3. **回滚不做撤销**：回滚是一次新的整图保存（这是 D7 要的语义），想退回上一步靠"再回滚一次"到更新的快照。
4. **图库无分页/筛选**：计划里写的 `按 name/tag/projectId/时间筛选` 未做，当前一次性拉全量（`order by updated_at desc`）。图上到几百张时需要补分页。

## 2. 1000 节点档位（规格 §11.4）

生产包实测（1000 节点 / 1000 连线 / 4 分组，fitView 到 10% 缩放）：

| 场景 | 结果 |
|---|---|
| 首次挂载（含建图 + 首帧） | **262–385ms**（`onlyRenderVisibleElements` 生效：884 节点 / 988 边实际进 DOM） |
| 指针拖动节点（20 帧） | p50 **16.6ms** / p95 18ms / max 18ms（≈60fps，拖动期冻结 `edges` 与障碍） |
| store 派发坐标变更（键盘/属性面板，30 帧） | p50 **116ms** / p95 134ms / max 224ms（见下方"已知限制"） |
| 边标签延迟渲染 | 缩放 1.88 → 30 个标签；缩到 0.44 → **0 个**（阈值 0.5） |
| 视口裁剪 | 平移后 DOM 内节点数随视口变化，全图 1000 → 视口内 884 |

本批为这一档位做的三处改动：

1. **冻结期不再白算**：`computedEdges` 以前无条件跑 `toFlowEdges`，结果被丢弃；现在冻结时直接复用上一批。
2. **大图放弃候选枚举**：`orthoPoints` 在障碍 >200 时把搜索窗从 `CHANNEL_MARGIN×8` 收窄到 `×2`，候选 >8 直接走规则路由（小图行为不变）。
3. **非拖拽移动也冻结**：键盘微调 / 属性面板改坐标时按"只有 x/y 变"判定为移动，冻结 edges 180ms 后再补算。

## 3. 本批修掉的问题

| 问题 | 现象 | 处理 |
|---|---|---|
| 空图/临时图被自动保存成新文档 | 刷新后打开落在空白画布（实测被写入 4 张空图）；压测临时图被存成真实图 | `useAutosave` / `enqueue` / `pagehide` 三处都加 `persisted` 守卫；导入 JSON 改为**显式** `saveDiagram`（不再依赖自动保存） |
| 保存链条被一次异常永久卡死 | `chain = chain.then(...)` 无 `catch`，抛一次后变成永久 rejected —— 之后所有保存静默失效、一直显示 dirty | `enqueue` 内 `try/catch` 捕获并显示到状态栏，链条继续；同时发现 `arch_patch_diagram` 的 `project_id` CASE 分支类型不一致（uuid vs varchar → 42804），前端改为"增量失败即退回整图保存"，SQL 里已修正 CASE |
| 压测脚本签名用错 | 早前 300 节点压测把 `createNode(did, {x,y}, ...)` 传错位（真实签名是 `createNode(nodeType, diagramId, position, overrides)`），节点坐标变 NaN，测出来的是"空画布"数据 | 本批脚本已按真实签名重写，数据全部重新采集（上表） |
| 只选筛选、不输关键字时结果不显示 | 空关键字分支优先渲染"输入关键字…"提示，D2 的下拉选了也看不到反应 | 空态条件改为 `query === '' && !filtered`，只筛不搜也能出结果 |

## 5. 已知限制与取舍

1. **1000 节点全屏时，非拖拽式坐标变更约 116ms/帧**：移动一个节点会让 1872 个 DOM 元素所在图层重绘
   （React 侧已把未变节点缓存住，剩下的是浏览器绘制成本）。指针拖拽走的是合成层 transform，仍是 16.6ms。
   再往下优化需要把节点渲染搬到 canvas，超出 MVP 范围，记录在案。
2. **增量保存需要重跑 SQL**：`arch_patch_diagram` 的 `project_id` CASE 已修正，但要用户重新执行
   [supabase/patch-diagram.sql](…/supabase/patch-diagram.sql) 才生效；没跑之前前端自动回退整图保存（功能不受影响，只是请求体大）。
3. **`arch_restore_snapshot` 同样需要重跑 SQL**；没装时回滚走"取 payload → 整图保存"，行为一致。
4. **快照缩略图是几何示意图**（矩形 + 直线，不画文字/图标）：列表里 50 张不会拖慢抽屉，也不需要额外存储。

## 本轮为过门禁补的修改

| 问题 | 现象 | 处理 |
|---|---|---|
| 拖入节点不选中 | `addNode` 只写了 `selectedId`，多选改造后选择态以 `selectedIds` 为准，拖进来属性面板不出现 | `addNode` / `addGroup` 同时写入 `selectedIds` |
| 任意手柄都连出同一条线 | `onConnectEnd` 拿**目标端**的吸附边当作源锚点，4 个手柄拖出同一组 `(source, target, anchor)`，被去重逻辑吞掉 | 记录 `onConnectStart` 的 `handleId`，源端用它，目标端按"朝向起点"取边 |
| 落点偏移十几像素 | drop 处理器把所有节点按 160×80 居中，而交换机/路由器是 120×60 | 尺寸改从 `COMPONENT_INDEX` 取默认值 |
| 非法数据能落库 | 保存前不做校验，`nodeType = 'not-a-type'` 这类值能写进库（DB 侧 `node_type` 只做 slug 正则约束） | `saveDiagram` 前跑 `validateDiagram(repair:false)`，返回 `reason: 'invalid'` + 字段路径，UI 直接展示 |
| 坐标无上限 | `x = 999999` 能通过校验 | `LIMITS.coordLimit = 100000`，节点/分组坐标超出即拒（V6 只要求有限数，这是工程护栏） |

## 已知取舍（不算未通过）

1. **10px 吸附**：拖动与落点都对齐到 10px 网格，落点误差最大 5px。A1 记录的是"不触发吸附取整"时的实测值 `(0, -2)`。
2. **DB 侧枚举**：`arch_node.node_type` 的 CHECK 是 `^[a-z0-9-]{1,32}$`（保证可扩展），枚举白名单由前端 Zod 保证；数据库只兜住形态非法值。
3. **D4 的执行位置**：`arch_save_diagram` 内部没有逐字段校验，非法数据在前端就被拦下，不会走到函数；函数侧仍有外键 / CHECK / 版本号约束兜底。
4. **快照**：门禁要求的"保存链路"已验证；快照表按每 5 次或 30 分钟落一份，验收期间产生了若干快照（version 递增属正常）。

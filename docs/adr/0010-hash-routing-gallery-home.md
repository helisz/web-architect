# ADR-0010 图库作为主页 + 每图一条 hash 地址

> 部分被 ADR-0016 取代（2026-11-05）：图库地址从 `#/` 改为显式 `#/gallery`，`#/` 仅作为兼容入口被 replaceState 改写；其余结论（hash 路由、路由即状态）不变。

- 日期：2026-11-04
- 状态：已采纳
- 相关：ADR-0004（无自建后端）、ADR-0008（保存策略）

## 背景

这一版之前，「图库」是画布页里的一个**视图开关**（`store.view`），启动时自动打开"最近更新的那张图"。用户提了三条：

1. 顶栏的「图库」图标按钮要去掉，改成最左边一个「‹」回图库；
2. 主页应该默认进**图库**，点开某张图才进画布；
3. 每张图要有自己的 URL 地址（用图的 hash/id 做子路径）。

第 3 条是本质变化：以前"当前是哪张图"只存在内存和 localStorage 里，刷新靠"最近更新"猜，分享链接根本带不上图。

## 决策

### 1. 用 hash 路由，不用 History API

`#/` = 图库，`#/d/<diagramId>` = 某张图，解析集中在 `apps/web/src/lib/route.ts`（`readRoute` / `diagramHash` / `navigateToDiagram` / `navigateToGallery` / `useRoute`）。

备选是 `/d/<id>` + 服务端 rewrite。放弃的理由：本项目是纯静态部署（ADR-0004），`apps/web/dist` 丢到任意静态服务器就能跑；History API 要求每个路径都回 `index.html`，等于给部署加了一条隐性前提，而 hash 不需要。代价是 URL 里多一个 `#`，可以接受。

### 2. 路由就是"打开哪张图"的唯一真相

- `store.view` / `setView` 删除；`App` 看 `route.kind` 决定渲染 `Gallery` 还是画布；
- `useBootstrap`（自动打开最近一张）删除，换成 `useRouteDiagram(route)`：只按 hash 里的 id 载入，`#/` 时 `closeDiagram()` 把图卸掉（自动保存随之停手）；
- 图库点卡片 = `navigateToDiagram(id)`，新建 = 存库后跳到新 id，切图逻辑只有一份；
- 图库里记住"上次打开的 id"（`arch:last-open`），只用于「返回画布」按钮和 tooltip，**不自动跳转**（用户明确要求主页就是图库）。

### 3. 离开前先刷盘

`flushPendingSave()`：只有"已落库 + 脏 + 不是在冲突/保存不可用/跟随者"时才同步存一次，然后才改 hash。理由：本地草稿只在**同一张图**重新打开时才会比对恢复，换图等于把这几秒的编辑丢掉。

### 4. 图不存在不白屏

载入报"图不存在 / 已删除"时，回图库 + 一条 toast 说明；其它错误（网络、表结构）仍然走 `StartupError` 页，并带一个「回到图库」按钮。

## 影响

- 深链接、刷新、书签、浏览器前进后退全部可用；
- 冒烟脚本要改：根路径没有画布了，先用 anon key 问 REST 挑一张**有节点**的图，再打开 `#/d/<id>`（`scripts/smoke.mjs`）；
- 快捷键在图库页关闭（`useShortcuts(enabled)`），避免在列表上按 `d` / `Delete` 动到图；
- 新增单测 `apps/web/test/route.test.ts`（7 例）盯住解析：不认识的 hash、太短的 id、带查询串的 id 都要落到图库。

## 备选与放弃理由

| 备选 | 放弃理由 |
| --- | --- |
| History API + 服务端 rewrite | 静态部署要多配一条兜底规则，违反"丢到哪里都能跑" |
| 图库仍是视图开关，只把当前 id 写进 hash | 后退键语义会乱（图库/画布切换是同一个 URL），而且两套状态容易打架 |
| 表里加短 hash 列做短链接 | 要改 DDL + 回填历史数据，本期收益不足；先用完整 UUID，将来想做短链可以再加一层别名表 |
| 换成另一张图时靠草稿兜底 | 草稿按图 id 存，换图就恢复不了，会实打实丢编辑 |

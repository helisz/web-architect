# ADR-0006：阶段 3 / 4 的导出与性能取舍

- 日期：2026-11-04
- 状态：接受

## 背景

阶段 3 要出 SVG / PDF / CSV，阶段 4 要过性能与视觉关。规格对这两块有明确要求，但实现路径需要现场定夺：

1. 规格 §12 建议 SVG「自绘序列化（rect + text + path）」，PDF 用 `jspdf` + `svg-to-pdfkit`（C12 已指出中文字体问题）。
2. 规格 §11.4 要求 300 / 1000 节点两档，`onlyRenderVisibleElements`、拖动时暂停边重算。
3. 规格 §5.2 有六条硬性视觉规则。

## 决策

### 1. SVG 用 `html-to-image` 序列化画布 DOM，不自绘

- 节点是 React 渲染的 HTML（圆角、图标、副文本、对齐），另外还有分组泳道、标签、选中态。
  自绘 SVG 等于把渲染逻辑写两遍，任何样式改动都要同步改导出，且很难做到"导出图 = 画布所见"。
- 代价：导出的 SVG 用 `foreignObject` 承载 HTML。**Chrome / Edge / Firefox / Safari 都能直接打开**，
  但 Visio / Figma / Illustrator 不渲染 `foreignObject`（这是所有序列化方案的共同限制，不是本项目的 bug）。
- 需要给设计工具时用 PNG 或 PDF。

### 2. PDF 用 2× 位图嵌入，不用 `svg-to-pdfkit`

实测：`jspdf` + `svg-to-pdfkit` 处理含 `foreignObject` 的 SVG 会得到**空白页**（3 KB PDF，无内容）。
换成位图嵌入后同一张图是 94 KB，内容完整。
- 分辨率取 PNG 2×（2080×1208 对应 A4 横向），打印清晰度足够。
- 若将来必须"矢量 + 中文"，路径是服务端/本地脚本跑无头 Chromium 打印（C12 的备选方案），不是前端能做到的。

### 3. 性能：三层缓存 + 两个开关，不做虚拟滚动的自我实现

| 措施 | 原因 |
|---|---|
| `onlyRenderVisibleElements`（≥300 节点启用） | ReactFlow 自带，视口外节点不渲染；小图关闭避免边缘抖动 |
| 拖动期间冻结 `edges` 数组与障碍数组 | 边长什么样由 `useInternalNode` 订阅驱动，不需要整批重建；障碍只对被拖节点敏感 |
| flow 对象 `WeakMap` 缓存（`flowMapping.ts`） | 每帧只改一个节点，其余节点对象身份不变 → `memo` 生效，避免 300 次重渲染 |
| `OrthoEdge` 路径 `useMemo` | 入参没变的边不重算 `buildOrthoPath` |

实测 300 节点：连续移动 p50 160ms → **16.5ms**；真实拖动 p50 **16.6ms**（≈60fps）。

### 4. 视觉：以规格 §5.2 为准，唯一例外是节点文字居中

- 已落实：无 3D/投影/渐变/发光（浮层阴影只用于菜单与面板）、字体两族（`--font-ui` + `--font-mono`）、
  连线默认无箭头（`EDGE_DEFAULTS.arrow = 'none'`，阶段 4 修正）、泳道底色明度 ≥96%（`#F1F3F5 / #EFF6FF / #FFF7ED`）、
  默认尺寸 160×80（交换机/路由器 120×60，集群类 200×100）。
- **未按规则 5 左对齐**：节点是"图标在上、标题 + 副文本在下"的居中版式（draw.io / Visio 同款），
  左对齐会让图标与文字错位。此条留待产品确认后再改，见验收记录"已知取舍"。

## 影响

- 导出三件套（PNG / SVG / PDF）走同一条渲染路径，颜色、字体、位置与画布一致；CSV 是独立的扁平表。
- 性能优化全部在渲染层，schema 与持久化格式没变，旧数据无需迁移。
- 视觉例外只有一条，且是"看起来更好但违反规则字面"的类型，需要产品拍板。

# ADR-0009 分组标签与文本类节点

- 日期：2026-11-04
- 状态：已采纳
- 相关：ADR-0005（图标只存 key）、ADR-0008（保存策略）

## 背景

产品在 v1.23 之后提了 6 条需求，其中 5 条落在「画布上的元素」这一层：

1. 分组要能换图标、能写副文本，图标与标题第一行对齐；
2. 左侧「结构」区要有 **服务器 / 集群 / nginx** 三个预设分组；
3. nginx 的图标要换成官方的「N」方块标记，不要 NGINX 全称 wordmark；
4. 左侧要新增「文本」区：标题、文本、便利贴、注释（注释气泡的尖角可拖方向）；
5. 多选要能批量改文字和颜色，按「交集」只改最小内容；
6. 关窗口时提示保存。

## 决策

### 1. 分组副文本走正式字段（`arch_group.sub_label`）

备选是塞进 `extJson`（不动库）。放弃的理由：`extJson` 不参与 Zod 校验、导出 CSV 时容易漏、
以后想按副文本搜索也没有索引可用。正式字段要付的代价是**一次 SQL 重跑**，值得。

兼容措施：

- `DiagramGroupRow.sub_label` 声明成可选（`string | null`），读出来是 `undefined` 时兜成空串 ——
  **先刷前端后跑 SQL 不会炸**；
- Zod 用 `.default('')`，老快照 / 老导出 JSON 少这个字段也能过结构校验；
- `patch-diagram.sql` 顶部放 `alter table ... add column if not exists`，可重复执行。

### 2. 标题栏两行（42px），图标与第一行顶部对齐

`GROUP_HEADER_HEIGHT` 从 32 提到 42，标题 + 副文本两行，图标 `items-start` 对齐首行。
产品明确接受"组内节点可能被标题栏压住"这一视觉后果，所以不额外做透明/悬浮标题栏。

### 3. 预设分组只是"三件默认值不同的普通分组"

`GROUP_PRESETS` 只带 iconKey / label / subLabel / 尺寸 / 配色，拖入时作为 `addGroup()` 的 overrides，
落库后与手动建的分组完全等价 —— 不需要新的实体类型，也不需要新表。

### 4. nginx 图标自绘内联

官方包里只有 NGINX 全称 wordmark。项目规则禁止外链 / base64 图标（ADR-0005），
所以按产品给的 512×512 SVG 内联成新的图标集合 `arch`，注册两个 key：

- `arch:nginx`：绿色六边形 + 白色 N（品牌原色，默认给 nginx 节点和 nginx 预设分组用）；
- `arch:nginx-mono`：同形状、单色描边（跟随文字色，适合浅底/单色图）。

同时补 `tabler:letter-n`（纯字母 N）作为第三个备选，`devicon:nginx`（全称）保留但不再是默认。

### 5. 文本四类都是真节点

新增 nodeType `title` / `sticky` / `annotation`（`text` 保留），走同一个 `ArchNode` 组件按 nodeType 分支渲染。

关键取舍：**不做"装饰层"**。产品明确要求它们可连线、可进分组、可多选对齐，
所以它们必须和业务节点共享 Handle、分组归属、对齐/分布、撤销栈 —— 另起一套渲染层会把这些全部绕开。
默认配色放在 `TEXT_NODE_STYLE`（标题/文本透明底透明边、便利贴米黄、注释白底灰边），
之后照样能用固定色板改。

### 6. 注释尖角：自由角度 + 根部按射线求交

数据：`extJson.tailAngle`（度，0=右、90=下、屏幕坐标顺时针为正）。选 `extJson` 而不是新列的
理由：它是纯渲染参数，不参与布局和搜索，加列收益低。

几何：从矩形中心沿角度射一条射线，**与矩形边界的交点**就是尖角根部。
产品特别强调"左侧的尖角必须从左侧射出"，这种求交法天然满足 —— 不需要按四边/八方向分档。
纯函数在 `apps/web/src/canvas/tail.ts`，13 条单测钉住（含边界优先级的两种情况）。

交互：选中注释时在尖端画一个可拖的小圆点，指针相对节点中心的偏移直接反推角度，
拖动过程只改本地 state，松手才写回 store（避免一次拖动几百次状态更新）。

### 7. 多选按交集批量改

`multiEdit.commonFields()` 只返回**每个选中对象都支持**的字段，值不一致标 `mixed`。
- 全选节点 / 全选分组：名称、副文本、背景色、边框色、文字颜色、图标；
- 节点 + 分组：同上（分组的"文字颜色"落到 `titleColor`）；
- 混入连线：只剩名称（连线没有背景色和图标）；
- 全选连线：名称 + 线条颜色。

不支持宽高和图标以外的结构性属性 —— 一次把 20 个节点改成同一个尺寸多半是误操作。

### 8. 关窗口提示的判定抽成纯函数

`beforeunload` 只能弹原生框、文案改不了、也没法在自动化里稳定回归，所以把判定条件抽到
`unloadGuard.shouldWarnOnUnload()`：已落库 + `dirty` + 距上次成功写库 > 3 秒 + 自己是写者。
跟随者、冲突中、保存禁用、临时图都不拦（拦了也存不了，只会变成噪音）。

## 影响

- 数据库：`arch_group.sub_label` 一列；`arch_save_diagram` / `arch_patch_diagram` / `arch_diagram_payload`
  的列清单同步（否则增量保存会把副文本写丢）。
- 契约：`NODE_TYPES` 30 → 33；`ALLOWED_ICON_KEYS` 16 → 20。旧导出 JSON 不受影响（新 nodeType 只是多出来的枚举值，
  老文件里没有；`subLabel` 缺失有默认值兜底）。
- 测试：新增 `tail.test.ts`(13) / `multiEdit.test.ts`(8) / `unloadGuard.test.ts`(7)，
  `validate.test.ts` 补 2 条副文本用例，图标与 fixture 断言同步更新。

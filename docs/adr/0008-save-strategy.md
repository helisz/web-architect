# ADR-0008：保存策略与冲突收敛

- 状态：已采纳（2026-11-04）
- 关联：ADR-[0004](0004-no-backend.md)（无自建后端）、ADR-[0006](0006-export-and-perf-tradeoffs.md)（性能取舍）
- 影响文件：`apps/web/src/data/usePersistence.ts`、`saveScheduler.ts`、`tabLock.ts`、`draft.ts`、`viewportPrefs.ts`、`supabase/schema.sql`、`supabase/patch-diagram.sql`

## 背景

第一版自动保存是"变脏就 800ms 后存"。实测一次 2 小时的编辑会话（同一个人画一张图）写了 **约 300 次库**、60 条整图快照：

- 相邻快照中位间隔 61 秒，即平均每 ~12 秒就有一次写库；
- 一次保存 = `arch_diagram` 版本 +1、变更行 upsert，另外每 5 版再写一条整图 JSONB 快照（写入放大 20%）；
- 想事情停 1 秒、点一下颜色、拖一下节点都会各自触发一次。

同时，版本冲突（`VERSION_CONFLICT` 409）几乎都是"两个标签页在看同一张图"造成的，而其中大部分甚至不是内容打架 —— 只是版本号被推高了。

## 决策

### 1. 按"改动性质"分流，而不是一律抖 800ms

| 改动类型 | 策略 |
|---|---|
| 增删节点 / 连线 / 分组（结构指纹变化） | 空闲 **1 秒** 就存（这类操作不能等） |
| 改颜色 / 文字 / 位置 / 尺寸 | 空闲 **3 秒** 才存 |
| 连续编辑从不停手 | 距第一次变脏满 **30 秒** 强制存一次 |
| 两次写库之间 | 至少隔 **10 秒**，合并连续小操作 |
| 视口（平移 / 缩放） | **不进版本、不单独写库**，只存 localStorage，内容保存时顺带写 |
| Ctrl/Cmd+S、回滚、导入 | 立刻写，绕过节流 |

规则本体是纯函数 `nextDelay()`（`saveScheduler.ts`），12 条单测钉住，改阈值不会悄悄改行为。

### 2. 快照频率从"每 5 版"放宽到"每 50 版 / 30 分钟"

手动快照（"存为快照"）不受影响。代价：连续编辑时快照粒度变粗，靠手动快照兜底。

### 3. 本地草稿兜住"拉长间隔"的风险

每 1.5 秒把当前图覆盖写进 `localStorage`（同步、不联网）。下次打开同一张图时，如果草稿版本与库内一致但内容不同，就自动恢复并提示；保存成功后立刻清掉草稿。断电最坏丢 1.5 秒，而不是 30 秒。

### 4. 一张图只让一个标签页写（跨标签页租约）

`localStorage` 里放租约 `arch:writer:<diagramId>`，持有者每 4 秒续租，12 秒没续上视为原主已消失。非持有者（follower）**不发保存请求**，界面上给出提示；在本页真的动手改就自动接管（对侧下一个心跳退位）。

### 5. 冲突先自动重定基，再问人

`VERSION_CONFLICT` 时先拉一次库内内容：若它与我们"上次成功保存的基线"**完全相同**，说明只是版本号被推高，不是真冲突 —— 把基线和版本号对齐后自动重试一次。真的内容打架才弹"覆盖 / 重新载入"。

## 结果

同一套操作下的实测（CDP 打桩计数，不落库）：

| 场景 | 改造前 | 改造后 |
|---|---|---|
| 12 次属性微调（每次间隔 0.7 秒） | ~12 次写库 | **1 次** |
| 5 次平移 / 缩放 | 5 次（跟上一次内容改动合并时） | **0 次** |
| 新增一个节点（并立刻改属性） | 1 次（800ms 后） | 1 次，**1075ms 后** |

多标签页：第二个标签页会自动降为跟随者，不再抢版本号；真冲突时先尝试重定基，只有内容真的重叠才打断用户。

## 代价与已知限制

- **"已保存"会晚 3 秒**：状态栏在这期间显示"未保存"，属预期；想立刻落库用 Ctrl/Cmd+S。
- 视口改为本地优先：换设备打开时视口是库里上次内容保存时带的值，不是最新平移位置。
- 极端情况下（两个标签页交替编辑）仍可能冲突，此时降级为原有的人工处理。
- localStorage 不可用（隐私模式）时草稿与视口记忆静默失效，保存逻辑不受影响。

# AI 解析架构图：评估与实施计划

日期：2026-11-05
状态：**已实现（B1–B7 全部完成）**，线上可用
关联：图库「新建」、`packages/schema`、`apps/web/src/components/Gallery.tsx`、`apps/web/src/ai/*`

## 1. 需求（用户 2026-11-05）

1. 可配置模型，**配置只存本地**（不进 Supabase、不经过任何我们的服务）。
2. 图库「新建」时分流：**空白**（现有行为）/ **AI 解析**（新）。
3. AI 解析：上传一张架构图 → 解析成我们的 JSON 格式 → 在画布中尽量还原原图。

## 2. 已拍板的取舍

| 决策 | 结果 | 后果 |
| --- | --- | --- |
| 模型接入 | 多家，默认 OpenAI 兼容 | 适配器模式（openai-compatible / anthropic / gemini），新建档案默认第一个 |
| Key 存储 | 本地口令加密（PBKDF2 + AES-GCM，localStorage 存密文） | 忘口令 = 配置清零，必须重配；解密后 key 只在内存 |
| 上传方式 | 点选文件 / 拖拽 / 粘贴截图（不做 URL） | 三种都要可用，粘贴走 `paste` 事件取 `clipboardData.files` |
| 布局 | 先按原图相对坐标落图，提供「一键整理」 | 位置贴近原图；整理调用现有自动布局 |
| 解析范围 | 节点 + 连线 + 分组/边界框 + 连线文字 + 节点类型推断 | 需要分组虚线框识别与 edge label；不做云厂商 logo 识别 |
| 结果处理 | 直接落图（无预览确认） | **必须整批一条撤销**，否则用户无法反悔 |
| 原图背景 | 不保留 | 不占存储、无隐私残留；图片只在一次请求里存在 |

## 3. 技术要点

- **浏览器直连**：静态站没有后端，请求从页面直接发到用户配置的端点。CORS 按厂商不同：
  OpenAI 兼容端点一般可直连；Anthropic 需 `anthropic-dangerous-direct-browser-access: true`；
  Gemini 可直连；Ollama 需用户设置 `OLLAMA_ORIGINS`。配置页把这些写成提示。
- **图片预处理**：长边压到 ≤1536px、转 JPEG(q0.85)，并在图上叠一层带坐标标签的辅助网格
  （模型对"第几列第几行"的定位比裸像素坐标稳），随后让它输出归一化 0..1 坐标。
- **结构化输出**：OpenAI 兼容用 `response_format: json_object`；Gemini 用 `responseMimeType:
  application/json`；Anthropic 用提示词约束 + 严格 JSON 解析。统一用 Zod 校验，失败重试一次
  （把校验错误回喂），仍失败则报错并保留图片以便重试。
- **落图映射**：`x = padding + nx * 可用宽`，节点宽高按原图相对尺寸换算并夹到 schema 下限
  （节点 64×40、分组 120×80）；连线两端必须存在，重复边去重；分组按包含关系归属。
- **一次撤销**：整批写入用 `withHistory` 的单条 key（如 `ai-import:<batchId>`），
  保证 `Ctrl+Z` 一次清空本次导入。
- **密钥安全**：PBKDF2-SHA256(210k 次) 派生 → AES-GCM 加密整个配置 JSON；
  localStorage 只存 `{v, salt, iv, cipher}`；解锁失败计数与"清除所有配置"入口都要有。

### 4.1 实际落地与计划的差异

| 计划 | 实际 | 原因 |
| --- | --- | --- |
| 图片叠坐标网格再让模型给坐标 | **没做**：直接让模型给 0–1 归一化坐标，落图按比例换算 | 网格在图里会被当成内容，反而干扰识别；归一化坐标实测足够（mock 与真图结构一致），且省一次图像变换 |
| Zod 校验 + 回喂校验错误重试 | 自写 `parseSchema` 整理 + **只在 JSON 不可解析时**重试一次，重试提示只强调"纯 JSON" | 我们的字段少、容错比严格校验更实用（坏一个元素不该让整张图失败）；回喂错误会多花一次图片输入的钱 |
| 分组按"包含关系"归属 | 提示词让模型直接给成员 key，我们算包围盒 | 模型给框坐标普遍偏移，给成员关系更可靠 |
| Anthropic 用纯提示词约束 JSON | 同 B1 的适配器 + 重试机制，行为一致 | 减少分支 |
| 「重新解析」按钮（保留上次上传的图） | 弹窗内保留图片 + 「重试」；关闭弹窗即丢弃 | 需求是"不保留原图"，弹窗内的重试已覆盖真实场景 |

## 5. 风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 模型空间定位漂移、中文小字漏识别 | 还原度不足，用户失望 | 叠网格；文案定调"80% 起步、人工收尾"；保留原图以便重试 |
| 无预览 + 直接落图 | 识别偏了要手工删 | 整批一条撤销 + "重新解析"按钮（保留上次上传的图） |
| 口令遗忘 | 配置不可恢复 | 配置页明写；提供导出/重新配置引导 |
| CORS 被端点拒绝 | 用户以为功能坏了 | 报错里直接说明"该端点不允许浏览器直连"，并给出对应厂商的解法 |
| 密集中文图 token 爆炸 | 超时/费用 | 长边 1536、JPEG 压缩、必要时"高精度模式"分两遍（v2） |
| 第三方 logo 识别 | 商标风险 | v1 明确不做，只做关键词→我们图标的映射 |
